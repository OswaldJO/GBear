# GBear — Features and Inner Workings

This document describes **how the app behaves today** and **where implementation lives**. For a short, commit-adjacent summary of recent changes, see `source control log.md`.

---

## Product shape

- **SwiftUI** app with a tabbed shell: **Library**, **Emulators**, **Paths**, **Streaming**. Controller mapping is **companion-only** (no **Controllers** tab on the Mac app).
- **SwiftData** persists emulators, game folder paths, and library games. Store file: see `PersistenceStoreLocation` (default under Application Support).

---

## Library tab

### Sidebar

- **All** — every visible game (emulator-linked + standalone Mac/Epic-style entries that pass filters).
- **Mac Games** — games with **no** `emulatorUUID` (native Mac adds, Epic imports, etc.). Context menu can clear only these entries.
- **Per-emulator** — games linked to that `EmulatorProfile`.
- **Linked emulators** (`LibrarySidebarSelection.emulatorGroup`) — profiles linked in Emulators show as **one row named after their platform** (small link icon after the name so names stay left-aligned, for example **Dreamcast** for Flycast + Redream) in place of their own rows. Rows are sorted alphabetically with the unlinked emulators. The group lists every member's games, and a file path that more than one member owns shows once (`RootView.visibleLibraryGames` keeps the default's row). Tiles use the default emulator's cover crop. The context menu has **Rename…** and **Clear Games for …** per member. **Rename…** sets a custom section name (`EmulatorLinkService.rename`), stored as `EmulatorProfile.linkGroupName` on every member (kept when members are added through Link, cleared when a profile leaves the group); empty or the platform name goes back to the platform name (`Group.platformName`). The custom name is also used in Emulators' link captions and the search prompt. Linking or unlinking moves the selection to the group row, or back to **All** (`reconcileSidebarSelection`).
- **Count** — footer under the sidebar shows how many games are in the selected list (All, Mac Games, Flycast, …). Hidden on the Manage Providers, Storefront Manager, and ROMM panes.
- **Storefront Manager → Show Manager** — one sidebar row that opens `StorefrontManagerView`. At the top, a **Storefronts** card has a checkbox for **Epic Games**, **Steam**, **GOG** (`StorefrontSettings.enabled`, `UserDefaults` `Storefronts.Enabled`, default Epic only). Unchecked storefronts are not imported and their games are hidden from the grid (rows are kept). Then a login card per storefront (`StorefrontLoginCard`) with **Only show installed games in library** (`Storefronts.OnlyInstalled`, per storefront) and a single **Sign In…** button (modeled on GameNative); Steam also has a collapsed **Steam Web API key (optional)** section. Last, one import card with per-storefront counts and the last result.
  - **Sign-in** (`StorefrontLoginSheet`):
    - **Steam (native, `SteamLoginView` + `SteamAuth`):** the Steam client's `IAuthenticationService`, called as plain HTTPS form posts to `api.steampowered.com` (no JavaSteam). Two tabs:
      - **Password:** `GetPasswordRSAPublicKey` → password encrypted with RSA PKCS#1 (`SecKeyCreateEncryptedData`, key built from Steam's modulus/exponent) → `BeginAuthSessionViaCredentials` (`platform_type` **MobileApp**, `website_id` Mobile, persistent; BJ-122: WebBrowser tokens can't be renewed over the Web API). Then, by `allowed_confirmations`: approve in the Steam Mobile app (polling, with **Enter a Steam Guard code instead**), a Steam Guard code, or an emailed code (`UpdateAuthSessionWithSteamGuardCode`).
      - **QR Code:** `BeginAuthSessionViaQR`; the `challenge_url` is drawn with `CIQRCodeGenerator` and refreshed from `new_challenge_url`; an expired session restarts automatically.
      - Both poll `PollAuthSessionStatus` every `interval` s until a refresh token arrives. The SteamID is the token's JWT `sub`; the display name is the persona (`GetPlayerSummaries` with the access token) or the account name. The password is never stored.
      - Owned games: `SteamAuth.accessToken()` reuses the saved access token (`steam.accessToken` in the Keychain) while it has 5+ minutes left, else mints one with `GenerateAccessTokenForApp` (`renewal_type` 1, saves a rotated refresh token) → `IPlayerService/GetOwnedGames` with `access_token=`. AccessDenied (15) there means a pre-BJ-122 WebBrowser token and asks the user to sign in again. If that fails and a Web API key is saved, the key is used instead. Older OpenID sign-ins (SteamID + key) keep working.
      - Steam errors come from the `x-eresult` header (`SteamAuthError`: 5 wrong password, 65/88 bad code, 84 rate limited, 9/27 expired).
    - **GOG / Epic:** embedded `WKWebView` (non-persistent data store) that captures the code itself. GOG: GOG Galaxy OAuth client; the code arrives on the `embed.gog.com/on_login_success` redirect. Epic: Epic Games Launcher OAuth client; the `authorizationCode` JSON page is read. Social sign-in buttons (Google, Steam, Discord, Xbox) open pop-ups; the coordinator is the `WKUIDelegate` and stacks each pop-up over the page in the same container, closing it on `webViewDidClose` (BJ-121). A **Trouble signing in?** section at the bottom of both windows opens sign-in in the browser: Epic takes the pasted `authorizationCode`, GOG takes the pasted `on_login_success` address or code.
    - Refresh tokens (all three stores; rotated on each import) and the optional Steam key live in the Keychain (`StorefrontCredentials`, service `com.gbear.storefronts`); account names and the SteamID live in `UserDefaults`. **Sign Out** clears the token and SteamID but keeps the Steam key.
  - **Import** (`StorefrontImporter`), for each checked storefront:
    - **Installed from disk:** Steam `libraryfolders.vdf` + `appmanifest_*.acf` with StateFlags bit 4 (`SteamClient`, `VDF` parser). Epic launcher `.item` manifests (`EpicClient`, replaces `EpicInstalledGamesImporter`). GOG `goggame-<id>.info` in `/Applications`, `~/Applications`, `~/GOG Games` app bundles (`GOGClient`).
    - **Owned list when signed in:** Steam Web API (sign-in access token, or the optional key); GOG `account/getFilteredProducts`; Epic library-service records + catalog bulk items. Epic records in the `ue` namespace or a private sandbox are skipped; catalog items with `mainGameItem` or a category starting with `addons`, `digitalextras`, `engines`, `assets`, `asset-format`, `plugins`, `projects` or `type/format-item` (DLC and Unreal / Fab marketplace content) are not games (BJ-123). Rejected app names are remembered (`Storefronts.Epic.NonGameAppNames`) and left out of the owned set, so their rows are removed. Catalog lookups run only for app names not already in the library, except one full re-check whenever `EpicClient.gameFilterVersion` goes up.
    - **Supported systems:** `LibraryGame.storefrontPlatforms` (comma-separated `GamePlatform`: `mac`, `windows`, `linux`; nil = unknown). GOG fills it at import from `worksOn` in `getFilteredProducts`; Epic from the catalog item's `releaseInfo[].platform` (`gameFilterVersion` 3 re-checks existing rows once). Steam (and GOG rows still unknown) are looked up the first time the inspector opens via `StorefrontPlatformLookup` (Steam `store.steampowered.com/api/appdetails?filters=platforms`, GOG `api.gog.com/products/<id>` `content_system_compatibility`; no sign-in) and saved. The inspector's **storefront section** (Steam / Epic Games / GOG, in place of the ROMM section) shows **On this Mac** (Installed / Not installed) and **Works on** macOS / Windows / Linux; an installed game counts as Mac. No Mac build shows an orange note that it needs CrossOver or another compatibility layer.
    - **Only show games that work on Mac** (per storefront checkbox under the installed one; `StorefrontSettings.onlyMac`, `UserDefaults` `Storefronts.OnlyMac`): `isVisible` hides games whose known platforms lack `mac`. Installed games always show, and games not checked yet stay visible until known. After every import, and when the box is turned on, `StorefrontImporter.fillMissingPlatforms` looks up Steam / GOG games with no platforms (Steam spaced 1.5 s apart for its ~200 requests / 5 min limit, GOG 0.3 s), saving every 10; the import card shows "Checking which systems N game(s) support…" and each store's "N work on Mac" count.
    - **Library rows:** `librarySourceID` = storefront raw value, `storefrontGameID` (Epic app name / Steam app id / GOG product id), `storefrontInstalled`. Uninstalled owned games use a launcher URL as `romPath` (`steam://rungameid/…`, `goggalaxy://openGameView/…`, `com.epicgames.launcher://apps/…`).
    - **Removal:** a storefront row that is neither installed nor owned (or not installed while signed out) is removed on import. If the owned list fails to load, rows are kept and only marked not installed.
    - **Covers:** new rows get store art (Steam `library_600x900_2x`, falling back to `header.jpg` via a HEAD check; GOG games-database vertical cover; Epic `DieselGameBoxTall`). The metadata fetcher skips storefront games that already have a cover. Legacy Epic rows are matched by `epicAppName` or path.
  - **Grid:** installed storefront games show a green check in the cover's top-right corner (`LibraryGame.isInstalledStorefrontGame`).
  - **Launch** (`GameLauncher.launchStorefrontGame`): Steam always via `steam://rungameid`; Epic via the launcher URI, falling back to the installed app; GOG opens the installed app, otherwise the game in GOG Galaxy.
  - **Blocking:** removing a storefront game blocks `storefront/<store>/<id>`, so it stays blocked whether installed or not.
- **ROMM → Show ROMM** — opens `RommSettingsView`. See **ROMM** below.
- **Cover Art and Metadata → Manage Providers** (`ScreenScraperSidebarRow`; the pane is still titled Screen Scrapper) — detail pane for ScreenScraper in this order: **login**, **Actions** (full-library scrape), **Automatic matching**, **Region priority** at the bottom (reorderable list; first available cover/title region is used). **Only Scan Missing** (default on) skips games that already have scraped cover art (ScreenScraper or TheGamesDB); uncheck to scrape the whole library again. The panel also has **IGDB keys**, **SteamGridDB API key**, and **TheGamesDB API key** cards (in fallback order). When you are not signed in, the scrape fetches covers from whichever of those keys are saved.

### Toolbar (Library)

- **Add Game** — `NSOpenPanel` for app/executable/directory; creates `LibraryGame` with no emulator. Also unblocks that path if it was on the blocked list.
- **Scan Paths** — `GamePathScanner.scan` plus `EpicInstalledGamesImporter.importInstalledGames`. It links local cover files, then `scrapeNewGames` looks up covers for added games that still have none. Scan is **one level deep** (files + immediate subfolders). After scanning, **prunes** emulator-linked games whose ROM/file is missing when that location is **reachable** (`ScanSummary.removedMissing`) — including leftovers from a Paths folder that was later removed. Also removes leftover per-file rows inside folders now treated as one game (`removedNested`). Games under an offline/unmounted volume are kept. Startup still removes games whose **emulator** no longer exists. Blocked paths are never inserted (`ScanSummary.skippedBlocked`, reported in the scan alert).
- **Import Storefront Installed Games** — `StorefrontImporter.importAll` for every checked storefront (also runs at the end of **Scan Paths**; skips blocked games). See **Storefront Manager** below.
- **ScreenScraper Login** — presents `ScreenScraperSettingsSheet`.
- **Manage Blocked List** — presents `BlockedGamesSheet`: games removed with **Remove from Library**, with emulator name, removal date, and path. It has per-row **Unblock** and **Unblock All**, and the next Scan Paths re-adds unblocked games. The list is `LibraryBlocklist` (JSON in `UserDefaults` key `Library.BlockedGames`, keyed by the lowercased standardized path the scanner compares with). Only the grid context menu's **Remove from Library** (`RootView.deleteGame`) adds entries. **Clear All Games** / **Clear Games for …** / **Clear Mac Games**, orphan cleanup, and scan pruning do not. Help → **Games missing after scan** explains this.

### Grid and play

- `LibraryGamesGridView` / `GameLibraryTile`: tap for play/info overlay; play goes through `GameLauncher`. Tile width comes from the **cover size slider** at the bottom right of the grid (110–320 pt in 25 steps of 8.4 pt, default 160, saved as `Library.CoverWidth`); the grid fits as many columns as possible between equal 20-pt outer margins and spreads spare width into the column gaps. Height follows that game’s emulator **cover art size** (`CoverAspectRatio`, default **2:3**). Mixed **All** rows can be uneven. The whole cover is shown (**fit**, never cropped): each tile is sized to its image's own shape, at card width or capped at that emulator height (`GameLibraryTile.coverSize`, fed by `CachedCoverThumbnail.onImageSize`), and the rounded corners, badges and Play/Info overlay follow the image's edges. Tiles are top-aligned in each row, titles take only the lines they need (up to 3; **Hide Names / Show Names** in the toolbar's ⋯ menu, under Manage Blocked List, turns them off; `Library.ShowsTitles`, default on), and each row is as tall as its tallest tile, so mixed-emulator rows don't leave big gaps.
- **Order:** `DiscGroupService.librarySort` (disc groups together, then title, then `sortOrder`). Titles compare with `localizedStandardCompare` on `sortTitle(for:)`, which turns standalone Roman numerals 1–39 into digits so **II** sorts between 1 and 3 (BJ-124). The inspector's **Ignore Roman numerals when sorting** toggle (shown only when the conversion changes the title; `LibraryGame.ignoresRomanNumeralsInSort`) is the per-game exception list.
- **Search** (`RootView.librarySearchText`, `.searchable(placement: .toolbar)` on the game-grid detail only): narrows the **selected sidebar section** (`sectionGames` → `filteredGames`). Every whitespace-separated term must match (`localizedStandardContains`, case/diacritic-insensitive) somewhere in display name, original title, ROM file name, platform hint or emulator name (“Mac” for Mac games). Sidebar count footer shows matches; empty result → `ContentUnavailableView.search`. On a narrow window the field collapses to a magnifying-glass button beside the toolbar `>>` overflow.
- **Controller navigation** (`LibraryControllerNavigator`, started from `RootView`'s `.task`): any connected controller drives the window. Focus is in one of the **areas** (`LibraryControllerNavigator.area`), left to right: **sidebar** (only while expanded), **covers**, **Info column** (only while open), **toolbar**; on Emulators / Paths / Streaming it's **page** then **toolbar**. **L2 / R2** cycle through them in a loop (`RootView.controllerAreas`). **L3** collapses / expands the library sidebar (`RootView.toggleLibrarySidebar`, `columnVisibility`); collapsing it while it has focus moves focus to the covers. Focus starts on the covers. The focused item gets an accent ring (`controllerRing`; white on the selected sidebar row); the selected cover keeps a faint ring while another area has focus. **Covers:** D-pad / left stick moves between covers (first press selects the first; held directions repeat after 0.4 s; up/down move by the column count; the grid scrolls to it; the selected cover's 1.03× pop is animated with the scoped `.animation(_:body:)` so only the scale animates, not the cover's position when the lazy grid re-places a just-created row; tiles drop inherited animations and seed their cover from `CoverImageCache.image(for:)`'s in-memory `NSCache`, so tiles the lazy grid rebuilds appear at their final size instead of sliding in, BJ-126); **A** shows the Play/Info overlay, **A** again plays; **Back** closes the overlay, then clears the selection. **Sidebar:** up/down changes the selected section (every row, including Storefront Manager / ROMM / Cover Art); **A** or **Back** goes to the covers. **Info column:** `LibraryGameInspectorView.controllerItems` lists its controls top to bottom (name, Roman-numeral toggle, path / Show in Finder, ROMM download / link, Launch with, disc set rows and buttons, cover buttons, detected covers); up/down moves, **A** uses the control (name and game path open the on-screen keyboard, buttons run, Launch with steps to the next emulator), left/right steps Launch with or moves a disc / detected cover earlier or later. **Back** closes the column. **Toolbar:** the toolbar's buttons mostly sit in the `>>` overflow menu, which apps can't highlight, so focusing the toolbar shows a **controller strip** under it (`RootView.controllerToolbarStrip`) with the four tabs, Search (opens the on-screen keyboard; results filter live as you type), Add Game, Scan Paths, Import Storefront Games, ScreenScraper Login, Manage Blocked List and Hide/Show Names; left/right moves, **A** activates (picking a tab moves focus into it: covers for Library, the page for the others), **Back** goes back to the covers. **Page (Emulators / Paths / Streaming):** `ControllerPageNavigator` finds controls by walking the window's `NSView` tree instead of wiring each Form by hand: AppKit-backed controls SwiftUI puts on screen (pop-up menus, switches, editable text fields, sliders, icon buttons) plus SwiftUI-drawn buttons, which only show up as SwiftUI's private `_FocusRingView` (small rings are buttons; full-width rings outline rows and are skipped). The D-pad moves to the nearest control in that direction (scrolling it into view); **A** clicks it (a real mouse event posted at its center), opens the on-screen keyboard for a text field (the result is typed through the field editor so the SwiftUI binding updates), or steps a pop-up / slider; **left / right** on a pop-up or slider changes its value instead of moving; **Back** goes to the toolbar. The outline is a click-through child window (`HighlightWindow`), because views added to the SwiftUI hosting view weren't drawn; it hides while the keyboard is up. Plain tappable SwiftUI rows without a focus ring (e.g. Emulators library search results) aren't reachable. **Anywhere in the library:** **Select** (Share / Create / View) opens the Info column for the selected game and moves focus into it, or closes it and returns to the covers — on release, and only if no shoulder button was pressed with it, since Select is also the volume / brightness modifier (shoulders pressed with Select are ignored until let go) (closing with the mouse also returns focus); **L1 / R1** step to the previous / next game in grid order and the open Info column follows; **Start** (Options / Menu) plays the selected game immediately, skipping the overlay; **Square / X** and **Circle / B** shrink or grow the covers one slider step (8.4 pt; the slider itself now snaps to the same steps), repeating while held. **Back** is **Triangle / Y** (Circle is taken by cover size). **Keyboard:** on every tab, the arrow keys and Return go through the same commands (`LibraryControllerNavigator.handleKey`, a local `keyDown` monitor; skipped with ⌘ / ⌥ / ⌃ / ⇧ held, while the on-screen keyboard is up, or whenever the controller would be blocked). While a text field is being edited, keys go to the field except: in a single-line field ↑ / ↓ resign it and carry on navigating; in the toolbar search field ↓ or Return go to the covers and ↑ to the strip. Return on the strip's **Search** focuses that real search field (`RootView.focusToolbarSearchField` → `LibraryControllerNavigator.toolbarSearchField`; SwiftUI's `.searchable` is **not** an `NSSearchToolbarItem` but its own `AppKitToolbarItem` (`com.apple.SwiftUI.principalSearchItem`) hosting a `SwiftUI.AppKitSearchField`, so the lookup walks toolbar item views and the title bar, skipping the window content) instead of the on-screen keyboard (the controller still gets the on-screen keyboard), and Return on a page text field focuses it for typing (`ControllerPageNavigator.activate(fromKeyboard:)`). On Emulators / Paths / Streaming the arrows drive `ControllerPageNavigator` (switching tabs with the mouse puts the area on the page; its outline appears on the first arrow), ↑ with no control above goes to the strip and ↓ from the strip returns to the page. Keyboard moves set `commandFromKeyboard`, and an arrow against an area's edge fires `.leaveArea` instead of stopping (`RootView.leaveControllerArea`): covers' first column ← **sidebar**, last column / last cover → **Info column** (when open), top row ↑ **toolbar strip**, bottom row ↓ the **cover size slider** (new area `.coverSize`, accent ring around the slider; left / right step it like Square / Circle, up returns; also reachable by the controller only this way). Back the other way: sidebar → or top-row ↑ (to the strip), Info ← when the focused control has nothing to step (Launch with / disc / cover order step first), strip ↓. Down into a shorter last row lands on its last cover. The controller keeps stopping at edges (held D-pad repeats would otherwise fly out of the grid). The sidebar `List` only keeps AppKit keyboard focus after a click: setting `area` to anything else resigns it (`area` `didSet`), and an arrow while the sidebar's `NSTableView` (first pane of the split view, `isSidebar`) is first responder starts in the sidebar. The Select button's system gesture (macOS can use Share / Create for screenshots) is disabled via `preferredSystemGestureState` so GBear receives it. The navigator **polls** `GCController.controllers()` at 60 Hz rather than setting `valueChangedHandler`, because the streaming code owns those handlers and turns on `GCController.shouldMonitorBackgroundEvents` app-wide. So it gates itself: it acts only when GBear is the active app, its main window is key, with no sheet, modal or open / save panel (`NSOpenPanel.begin` isn't modal and can become main), and this Mac isn't hosting a stream (`GBearStreamHostManager.isVideoStreaming`) or joined to one as a guest (`GBearStreamGuestManager` connected/streaming). **Folder / file pickers** are the exception (`drivesFilePanel`: an `NSSavePanel` is key and the app / stream checks in `appBlockedReason` pass): instead of commands, `handleFilePanel` presses the panel's keyboard shortcuts — D-pad = arrow keys, **A** = ⌘↓ (open the selected folder), **Back** = ⌘↑ (enclosing folder), **Start** = Return (Choose / Open), **Circle / B** = Esc (Cancel), **L1 / R1** = ⌘[ / ⌘], **L2 / R2** = ⇧Tab / Tab (sidebar ↔ file list), **L3** = ⇧⌘H (home). `pressPanelKey` posts them on the HID tap with Accessibility, otherwise queues them with `NSApp.postEvent`, which works because GBear isn't sandboxed so the panel is in-process. Entering or leaving a panel waits for every button to be released, so the press that opened or closed it doesn't act twice. It deliberately doesn't check `GBearHostLocalGamepad.isActive`: the host seats this Mac as co-op player 1 even when idle (BJ-125). Each change in whether it may act is logged (`Controller navigation active / blocked: <reason>` in `DebugLog`). After GBear comes back to the front, it ignores input until every button is released, so the press that switched apps (or a held game input) doesn't act in GBear. **Volume and brightness from the controller** (`checkSystemCombos`, every poll, in GBear or in a game): **Select + L1 / R1** lower / raise the volume and **Select + L2 / R2** the display brightness, repeating while held (0.4 s delay, then every 0.12 s). They post the Mac's own media key events (`NSEvent.otherEvent(.systemDefined, subtype 8)` with `NX_KEYTYPE_SOUND_UP/DOWN`, `BRIGHTNESS_UP/DOWN`, on the HID tap), so macOS shows its usual indicator and adjusts the current output / display; needs Accessibility (logged once without it). **Game shortcuts from the controller** (`checkGameCombos`, checked on every poll before the gate, only while another app is in front, since Start and R1 have their own jobs in GBear): **Start + R1** types ⌃⌘F into that app once per press to enter / exit full screen (needs Accessibility; logged and skipped without it). **Select + Start** held on one controller for 5 s quits that app (`quitFrontmostApp`; fires once per hold, never quits GBear). Both type real key presses through `typeShortcut` (`CGEvent` on the HID tap, like `GBearKeyboardPadStandIn`). Without Accessibility, quitting falls back to `NSRunningApplication.terminate()`, the same quit request. After ⌘Q, `ControllerDialogNavigator` watches that app for 60 s: every 0.25 s it reads the app's focused window through Accessibility (`AXUIElement`), treats it as a confirmation dialog if it has a sheet, a dialog subrole, is modal, or is under half the size of the app's largest window (so the main window's toolbar buttons don't count), collects its buttons and checkboxes (minus the close / minimize / zoom buttons), and outlines one with the shared click-through `HighlightWindow` (status-bar level, joins full-screen spaces). The outline starts on the dialog's default button (RPCS3's is **No**). While it's up, `checkQuitDialog` reads new presses only: D-pad moves, **A** sends `AXPress` (falls back to a mouse click at the button's center), **B / Y** press the dialog's cancel button or send Esc; Select / Start held from the combo are ignored. Holding **Select + Start** again while the asked app is still running calls `forceTerminate()` (`quitRequestedApp`), for dialogs Accessibility can't see. Once the app is gone (GBear waits up to 60 s so there's time to answer) GBear unhides and comes to the front (games GBear launched already do this through `GameLauncher`; this also covers Steam and other launches). `start()` sets `GCController.shouldMonitorBackgroundEvents` so the combos are seen while the game is in front, and the combo check disables the Share / Create system gesture so holding Select doesn't start a screenshot or recording.
- **On-screen keyboard** (`OnScreenKeyboardView.swift`: `OnScreenKeyboard` model + view, shown as a dimmed overlay in `RootView`): PlayStation-style layout — number row, three letter rows (`'` `,` `.` `?` on the right), and a bottom row of Shift, `@#:` (symbol layout), cursor ◀ ▶, Space, Delete and Done. While it's up, `LibraryControllerNavigator.fire` sends every command to `OnScreenKeyboard.handle` instead of the library: D-pad moves between keys (wraps; keeps the column through wide keys), **Cross / A** types, **Square** deletes, **Triangle** types a space, **L1 / R1** move the caret, **L2** toggles Shift (one-shot after a letter), **R2** or **Start** is Done, **Circle** closes. The **right stick** slides the keyboard around the window (squared response, 1100 pt/s at full tilt, clamped so it stays on screen; `OnScreenKeyboard.move`), and **L3 / R3** shrink or grow it (`Command.leftStickClick` / `rightStickClick`; outside the keyboard L3 toggles the sidebar) in 10 % steps from 1× (the original size, the minimum) up to 2× or whatever fits the window (`resize`). Size is drawn by scaling every metric and font rather than `scaleEffect`, so text stays sharp. Scale and position persist (`Controller.Keyboard.Scale` / `OffsetX` / `OffsetY`). Closing always keeps the text (`onCommit`); Search also gets `onChange` for live filtering. Special keys show the connected controller's own button glyph (`LibraryControllerNavigator.buttonSymbol`, from `GCControllerElement.sfSymbolsName`). Keys are clickable with the mouse; clicking the dimmed backdrop closes it.

### Inspector (Info)

- `LibraryGameInspectorView`: display name; for emulator-linked games — **File** (basename) and **Path** (full `romPath`, link-styled; tap opens **Finder** via `NSWorkspace.activateFileViewerSelecting`; orange **Not present** when the file is missing, with a **Download From ROMM** button underneath for ROMM games — see **ROMM**); for **Mac** entries with no emulator — editable game path + **Choose Game…**.
- **ROMM** (only when `rommStatus` is set, i.e. the game's emulator is linked to a ROMM platform): **Status** (**In ROMM** green / **Missing** orange) and **ROMM path** (the server's `full_path`, link-styled; opens `<server>/rom/<id>` in the browser).
- **Launch with** (emulator-linked games only): a menu of emulator profiles. The default is the game's library emulator, or the **group default** when that emulator is linked (`EmulatorLinkService.defaultLaunchEmulator`). Picking another stores `LibraryGame.launchEmulatorIDString`, and `RootView.launch` passes that profile to `GameLauncher.launch(game:launchEmulator:)`. The game stays in its library section and keeps its ROMM link; scans don't touch the override. A deleted override profile falls back to the default.
- **Multi-disc set:** link with suggestions or **Link with other discs…** sheet (`DiscGroupLinkSheet`); list linked discs with ▲/▼ reorder; **Reset order from filenames**; **Unlink this disc**. Linked discs share cover art and ScreenScraper `gameid`/`systemeid`; changes propagate via `DiscGroupService.propagateSharedState`.
- Cover art: choose file, **Search for Covers** across configured providers (title drops trailing `(USA)` / `(Disc 1)` tags; **Platform** defaults from the emulator profile), reorder detected covers, set primary, clear. Inspector preview uses the same per-emulator crop as the grid.

Grid tiles show a **Disc N** badge when the game is in a linked set and a disc number is parsed from the path/title.

**Key types:** `RootView.swift`, `LibraryGame.swift`, `CoverAspectRatio.swift`, `DiscGroupService.swift`, `DiscGroupLinkSheet.swift`, `LibraryControllerNavigator.swift`.

## Emulators tab

- Add/configure `EmulatorProfile`: executable path, GBear-style `{ImagePath}` / `{rom}` template, optional per-emulator ROM extensions.
- **Cover art size** — picker on create and edit (`CoverAspectRatio`): **2:3 (SteamGridDB)**, **4:3 (SNES)**, **1:1 (GBA, PSX)**, **3:4 (PS2, GC, WII, NES)**, **8:7 (NDS, 3DS)**, **3:5 (PSP, SWITCH)**, **16:9 (Screen / Banner)**. Stored as `coverAspectRatioRaw` (default `"2:3"` for SwiftData migration). Catalog/custom row fill infers a starting ratio from platforms/name; the user can change it before Add / Save.
- **Platform** — picker on create and edit (`screenScraperSystemId`, same ScreenScraper console list as manual cover search). Catalog/custom row fill infers a starting console; **Not set** falls back to catalog/name inference. Stored id is used for scrape `systemeid` and as the default **Platform** in inspector **Search for Covers**.
- **Link emulators** (`LinkEmulatorsSheet`, link button or context menu on a configured profile; `EmulatorLinkService`): links profiles that emulate the same platform into one library section named after that platform.
  - **Platform:** only profiles with the same platform can be linked, meaning the picked `screenScraperSystemId`, or the inferred one when it is **Not set** (the same value the list shows). A profile with no platform can't be linked.
  - **Default launcher:** the user must choose a **Default emulator** before **Link** is enabled. It opens the group's games unless a game picks another under **Launch with**.
  - **Storage:** `EmulatorProfile.linkGroupIDString` (shared UUID) and `isLinkGroupDefault`. The row shows "Linked with … in Dreamcast · default is …".
  - **Unlinking and repair:** **Unlink** in the sheet dissolves the group, and **Unlink from …** in the context menu removes one profile. `normalize` runs after edits and deletes: it drops members whose platform changed, dissolves groups with fewer than two members, and keeps one default. The edit sheet warns that changing the platform unlinks the profile.
  - **Scanning:** `GamePathScanner` keeps one row per path and no longer hands rows between linked profiles that scan the same folder. Unwanted rows owned by a linked profile are settled after every root is scanned (`deferredStale`): they go to a linked profile that still wants them, else they are deleted.
  - **ROMM:** `RommSync.blend` matches ROMM roms against the games of the whole group. ROMM-only downloads can go to any member's game folders.
  - **Automatic merge:** linking, unlinking (sheet or context menu), deleting a linked profile, or an edit that unlinks one runs `EmulatorLinkService.refreshLibraryAfterLinkChange` in the background. That is `GamePathScanner.scan` plus `RommSync.sync` (no cover scrape). Duplicates merge without pressing **Scan Paths**.
- **`{user_name}`** expands to the current macOS account short name at launch (for paths under `/Users/{user_name}/Library/...`). Leading **`~`** in an argv token is expanded. Absolute home paths in stored templates are normalized to `/Users/{user_name}/...` on save/startup (`LaunchArgumentTemplate`).
- Export/import configured profiles (optional `coverAspectRatioRaw` and `screenScraperSystemId`; older JSON keeps the current values on conflict overwrite). Bundled catalog + custom launch-argument presets live in `BuiltinEmulatorCatalog` / `CustomEmulatorLibraryStore`.
- **PS2:** catalog preset **ARMSX2** (`emulatorId: armsx2`); default startup **`-fastboot -- "{ImagePath}"`**. **AetherSX2** is not in the catalog; startup may retarget existing `AetherSX2.app` profiles to `/Applications/ARMSX2.app`.
- **Switch:** catalog presets **Ryujinx** (Default / Avalonia) and **Astris** (`emulatorId: astris`, `"{ImagePath}"`, `xci` / `nsp` / `xcz` / `nsz`). Astris is sandboxed, so `GameLauncher` hands it the game as an open-document event rather than argv (see Launch pipeline, BJ-128).
- **Add emulator:** choosing a catalog/custom row fills launch args, file types, a starting **platform**, and a starting **cover art size**; **display name** is filled only when that field is empty.
- **App Sandbox is off** for the Mac app (`GBear.entitlements`). Sandboxed callers cannot pass `NSWorkspace.OpenConfiguration.arguments` (system ignores them).

**Key types:** `EmulatorsView.swift`, `EmulatorProfile.swift`, `EmulatorLinkService.swift`, `LinkEmulatorsSheet.swift`, `CoverAspectRatio.swift`, `ScreenScraperPlatformPicker.swift`, `LaunchArgumentTemplate.swift`, `BuiltinEmulatorCatalog.json`.

## Paths tab

Per **selected emulator**:

- **Game folders** — scanned by `GamePathScanner` **one level deep**: each **file** and each **immediate subfolder** is one library game. Files inside a subfolder are not separate games (bin/cue dumps in a title folder stay one entry). Launch path for a folder is the best immediate file (`m3u` > `cue` > `gdi`/`chd`/`iso` … last `bin`). Point the path at the folder that *contains* those games, not a grandparent of lettered subfolders unless those folders are the titles.
- **Cover folders** — local images matched to ROM names on scan.
- **Exclude folders** — skipped during scan.
- **Toggle:** *Prioritize ScreenScraper art over local covers* — stored on `EmulatorProfile.preferScreenScraperCovers` (default `false`). Affects **auto-selected primary** cover after a metadata pass; all sources still accumulate in `coverImageOptions`.
- **Toggle:** *Auto-link multi-disc games on scan* — `EmulatorProfile.autoLinkMultiDiscGames` (default `false`). After each **Scan Paths**, `DiscGroupService.autoLinkAllEnabledEmulators` clusters games on that emulator with the same normalized base title (same logic as manual link suggestions) and links sets of 2+; `ScanSummary.autoLinkedDiscSets` reports count.

**Key types:** `PathsView.swift`, `GameFolderPath.swift`, `GamePathScanner.swift`, `DiscGroupService.swift`.

### RPCS3 / PS3 folder scanning

When a configured **game folder** belongs to an RPCS3 (or PS3-style) emulator, `GamePathScanner` uses **folder-aware** import instead of treating every file under `dev_hdd0/game` as a ROM:

| Detection | Behavior |
|-----------|----------|
| **Title folder** | Subfolder with `PARAM.SFO` and `USRDIR/EBOOT.BIN` (RPCS3 install) or `PS3_GAME/USRDIR/EBOOT.BIN` (disc dump layout). |
| **Title** | Read from `PARAM.SFO` (`TITLE`, else `TITLE_ID`, else folder name). |
| **Launch path** | Stored `romPath` is the **`EBOOT.BIN`** file; `GameLauncher` substitutes it into the emulator’s `{ImagePath}` / `{rom}` template (RPCS3 catalog default: `"{ImagePath}"`). |
| **Category filter** | Only **`GD`** (disc install) and **`HG`** (PSN/HDD install) folders are imported; patch/DLC/UCC/APPDATA-style siblings are skipped. |
| **File scan** | Loose **`.iso`** files sitting **directly** in the game folder are still imported. Inner assets (`.bin` tracks, etc.) are not separate games. |

**Typical path:** `~/Library/Application Support/rpcs3/dev_hdd0/game` assigned to the RPCS3 `EmulatorProfile` on the **Paths** tab.

**Rescan:** If a library row already exists for the same normalized `EBOOT.BIN` path, scan **updates the title** from `PARAM.SFO` (and can reassign emulator if the path moved profiles). Counts toward `ScanSummary.reassigned`.

**Limits:** Retail **GD** HDD folders often contain **game data only** (no `USRDIR/EBOOT.BIN`); RPCS3 boots those from the Blu-ray image or its internal list, not from an EBOOT path in `dev_hdd0/game`. Import those titles via **PS3 `.iso`** paths (or manual add) if you want them in the library grid.

**Help:** App menu **RPCS3 Game not launching** — if RPCS3 is already open, close it before launching a different PS3 game from the library (single-instance / open-document behavior).

**Key implementation:** `GamePathScanner.ps3LaunchPathIfPresent`, `ps3Metadata` / `parsePS3SFO`, `shouldIncludePS3Folder`, `isPS3StyleEmulator`, `preferredLaunchFile`.

## Metadata and ScreenScraper

- **Provider order:** **ScreenScraper API v2** (`https://api.screenscraper.fr/api2/…`) when the user is signed in, then **IGDB** (`https://api.igdb.com/v4/games`), then **SteamGridDB** (`https://www.steamgriddb.com/api/v2`), then **TheGamesDB** (`https://api.thegamesdb.net/v1.1/Games/ByGameName`, `include=boxart`) dead last because its monthly allowance is small. `CoverProvider.allCases` is the canonical order. Each backup runs only when the one before it produced no cover (or ScreenScraper was skipped because the user is not signed in), and only when its key is saved. A ScreenScraper disambiguation prompt is left for the user; the backups do not answer it.
- **Credentials:** `MetadataCredentials` — `devid` / `devpassword` required; `ssid` / `sspassword` optional. Persisted in `UserDefaults` (see `docs/metadata-setup.md`). TheGamesDB uses the key the user pastes on Screen Scrapper (`MetadataCredentials.theGamesDBAPIKey`). IGDB uses the user's Twitch application Client ID + Client Secret (`igdbClientID` / `igdbClientSecret`); **Save keys** asks Twitch for a token to confirm them. SteamGridDB uses the user's API key (`steamGridDBAPIKey`, sent as a Bearer token); **Save key** runs one test search. With no key saved, that provider is skipped.
- **TheGamesDB backup** (`TheGamesDBClient`, hooked from `MetadataBackgroundFetcher.fetchAndSave`): name search on the emulator platform (`TheGamesDBPlatformMap`, including Genesis + Mega Drive). The search string prefers a clean title over a longer dump filename (`Yonder_The_Cloud_…__0100…__v0` loses to **Yonder The Cloud Catcher Chronicles**; underscores and Switch title ids are normalized in `RomTitleNormalizer`). Front box art only, and only when `pickTitleIsCompatible` accepts the title. Covers are chosen with the Screen Scrapper **Region priority** list: TheGamesDB regions map to `us` / `eu` / `wor` / `jp` / `kr` / `au`, and the first region in that list that has a front cover wins. If the full name has no cover, one follow-up search uses the title through the sequel number (`Fullmetal Alchemist 3 The Girl Who Succeeds God` → `Fullmetal Alchemist 3`) so a later region (Japan, when US, Europe, and World are empty) can still supply the box. That follow-up does not rename the library title. No ROM hash lookup. A miss sets `LibraryGame.theGamesDBCheckedAt` so the background pass does not spend the monthly allowance again; **Scrape library** retries. HTTP 403 stops further TheGamesDB calls for that batch. Downloaded art uses the same `CoverImageCache` path, so **Only Scan Missing** skips it. `remoteCoverSource` is `screenscraper`, `thegamesdb`, or `igdb`. ScreenScraper game ids are not filled from the backups.
- **IGDB backup** (`IGDBClient`, `IGDBPlatformMap`): `IGDBTokenStore` caches the Twitch app access token (`https://id.twitch.tv/oauth2/token`, `client_credentials`) until shortly before expiry; a 401 clears it and retries once. Search is `search "…"; where platforms = (…)` with `cover.image_id`, `alternative_names`, and `game_localizations` (region + cover). A game matches on its name, an alternative name, or a regional name; only a main-name match may rename the library title. Both backups use `MetadataService.backupTitleMatches` (stricter than ScreenScraper's check): the shorter title's words must all be in the longer one, and a one-word title must match exactly, so `Off the Game` no longer takes `Olympic Games Tokyo 2020`. Cover choice: a regional cover wins only when its region is first in **Region priority**, otherwise the main cover, otherwise the best-ranked regional cover. Images use `t_cover_big_2x`. Same sequel-number follow-up search as TheGamesDB. Misses set `LibraryGame.igdbCheckedAt`. A rejected Client ID / Secret stops IGDB for the rest of that batch. Limit is 4 requests per second; a 429 waits one second and retries once.
- **SteamGridDB backup** (`SteamGridDBClient`, `MetadataBackgroundFetcher.querySteamGridDB`): SteamGridDB games are not tied to a console, so there is no platform map and every emulator can use it. A Steam storefront game (`storefront == .steam`) is looked up first by app id (`/grids/steam/{storefrontGameID}`), and that match never renames the title. Otherwise the fetcher calls `/search/autocomplete/{title}`, keeps hits that pass `backupTitleMatches` (exact name first), and asks up to two of them for grids (`/grids/game/{id}`). Only static portrait grids are used (`dimensions=600x900,342x482,660x930`, `nsfw=false`, `humor=false`), highest `score` first. When nothing matches and the title has brackets inside a word, it searches once more with them joined (`SP(LR)ITE` → `SPLRITE`, `RomTitleNormalizer.joiningInWordPunctuation`). `backupTitleMatches` (all name-search backups) joins in-word punctuation on both sides, so `Sp(L/R)ite` = `SpLRite`, and ignores non-Latin words in the candidate (`スプライト`) when the query is written in Latin letters. `RomTitleNormalizer.searchQuery` keeps in-word groups and only strips tags after a space or at the end (BJ-117). Same sequel-number follow-up search as the other backups. Misses set `LibraryGame.steamGridDBCheckedAt`. A 401 / 403 (key rejected) stops SteamGridDB for the rest of that batch. `remoteCoverSource` is `steamgriddb`.
- **Matching waterfall** (`MetadataService`, per game):
  1. Pinned `screenScraperGameId` + `screenScraperSystemId` on `LibraryGame` (if set).
  2. **`jeuInfos.php`** hash lookup (`RomFingerprint`: MD5/CRC32/SHA1, `.cue`/`.m3u` payload, PS3 folder `dossier`) — requires resolved **`systemeid`**.
  3. **`jeuInfos.php`** exact filename (`romnom` + size + `romtype`).
  4. **`jeuRecherche.php`** fuzzy search with query variants (`RomTitleNormalizer`, `.hack` `//` forms, roman → arabic numerals).
  5. Auto-select from ambiguous set (user toggle) or `ScreenScraperDisambiguationCoordinator` sheet.
- **Platform resolution** before scrape: stored `EmulatorProfile.screenScraperSystemId` if set; else `EmulatorProfileLookup` → `EmulatorPlatformResolver` (catalog/name); fallback `MetadataSystemResolver` (`platformHint`, Epic → PC **135**); fallback **`RomPathPlatformResolver`** (longest matching **Paths** game-folder root). Scrape logs include `emulatorSystemeid=`.
- **Region priority:** Screen Scrapper **Region priority** list (`MetadataCredentials.screenScraperRegionPriority`) ranks ScreenScraper locales. Cover and title picks walk that order (optional filename/manual-search region is tried first). Default rank is US → Europe → World → Japan → France → Germany → Spain → Korea, then Italy / Portugal / Australia / ScreenScraper default. Older single **PreferredRegion** values migrate to the top of the list.
- **Manual search** (`CoverSearchSheet`, inspector **Search for Covers…**; also **Search manually…** in the disambiguation sheet): searches every provider in `CoverProvider.configured` at once. That is ScreenScraper when the build has dev credentials, IGDB with user keys, SteamGridDB with a user key, and TheGamesDB with a user key (sections appear in that order); unconfigured providers are skipped and the button hides when none are set up. It pre-fills the emulator’s platform and strips dump tags from the title (`Vandal Hearts II (USA)` → `Vandal Hearts II`; `Off the Game [0100F5201B452000][v0] (1.33 GB)` → `Off the Game`) because ScreenScraper `jeuRecherche` misses region/title-ID/size suffixes. The platform picker's ScreenScraper id maps to TheGamesDB / IGDB filters via `screenScraperSystemId`, and **Any platform** drops the filter. The cover region picker boosts one locale, then the rest of the priority list. TheGamesDB hits are sorted by that order, and IGDB picks a regional cover with it. Results are grouped per provider with console and region labels, with no strict title filter (`TheGamesDBClient.searchCoverList`, `IGDBClient.searchCoverList`, `SteamGridDBClient.searchCoverList`). SteamGridDB ignores the platform and region pickers. It shows the top 6 games with up to 3 covers each, keyed by grid id. Picking a ScreenScraper hit goes through `ScreenScraperDisambiguationCoordinator.applySelection` (pins the game id). Picking a backup hit caches the cover, makes it primary, sets `remoteCoverSource`, and renames only when `backupTitleMatches`.
- **Title safety:** `pickTitleIsCompatible` blocks wrong-platform fuzzy picks; Part/Vol numbers optional when subtitle matches (`.hack Part 1` ↔ `.hack//Infection`). Scraped title applied only when compatible (hash/exact always apply).
- **API limits** (`CoverProviderQuota`, persisted in `UserDefaults` `CoverProviders.QuotaStatus`): a provider at its limit is **blocked until it resets**. Its client then refuses requests without touching the network, and the fetcher skips it (`skipped`, log `screenscraper_skipped … reason=limit_reached` / `screenscraper_limit_reached`).
  - **ScreenScraper** (`ScreenScraperClient.requestJSON`): every reply's `response.ssuser` gives `requeststoday` / `maxrequestsperday` and `requestskotoday` / `maxrequestskoperday`. At the max, or on HTTP 430 / 431, it is blocked until midnight Paris time. HTTP 429 blocks it for 60 s, and 401 / 423 (API closed) for 30 min.
  - **TheGamesDB** (`TheGamesDBClient.fetchGames`): `remaining_monthly_allowance` + `extra_allowance` from each reply. At 0 or on 403 it is blocked for `allowance_refresh_timer` seconds, else until the 1st of next month (UTC).
  - **IGDB** (`IGDBClient.post`): no daily quota. `IGDBRequestSpacing` keeps requests ≥ 260 ms apart (4/s limit), and a second 429 in a row blocks it for 30 s.
  - **SteamGridDB** (`SteamGridDBClient.get`): no published quota. HTTP 429 blocks it for `Retry-After` seconds (60 s when absent).
  - **Whole scrape:** **Scrape library** does not start when every provider the scrape would use (`CoverProviderQuota.scrapeProviders`: ScreenScraper only with a user login, the others with keys) is blocked (`libraryScrapeLimitMessage`). A running scrape stops when they all become blocked (log `all_providers_at_limit`). Unprocessed games are left for later.
  - **UI:** the **Actions** card in Manage Providers lists each provider's remaining allowance or its resume time, and disables Scrape library when all are blocked. Saving a different ScreenScraper login, TheGamesDB key, IGDB Client ID, or SteamGridDB key clears that provider's block.
  - **Log:** each `usage provider=…` line ends with `limit=ok` or `limit=blocked_until=… reason="…"`, plus `used_this_cycle=N/M cycle_resets=<ISO time>` for ScreenScraper (its daily cycle starts at midnight Paris time, so not the user's calendar day). Manage Providers shows the same as "N of M requests used this cycle (resets <local time>)".
- **When covers are scraped:** `MetadataBackgroundFetcher` (name kept) has no background loop (BJ-118: the old 45 s loop re-checked every game daily, covers or not, and spent ScreenScraper requests that never appeared in a log). It runs for **Scrape library** (`startLibraryScrape`), **Search for Covers…** per game, and `scrapeNewGames(reason:)` after **Scan Paths**, **Sync ROMM** or a storefront import adds games (`RootView`; link changes do not trigger it). `scrapeNewGames` takes only games with no `metadataLastFetchAt` and no cover. For each, it first tries `localCoverForGame` (image beside the game or in a nearby covers folder) and applies it, skipping that game; the scan has already linked matching cover files by then. Nothing left means no scrape and no log. Otherwise it runs like **Scrape library** (same progress card, titled "Finding covers for new games…"), logs `trigger=new_games reason=…` and `local_covers_applied=N`, and saves the log to Downloads without revealing it in Finder. A request that arrives mid-scrape runs right after it (`newGamesScrapePending`). Games it cannot match get `metadataLastFetchAt` and are left to **Scrape library**. **Only Scan Missing** (default on) filters that full scrape to games that already have scraped covers (`LibraryGame.hasScreenScraperCover`, including TheGamesDB art in the cover cache). Session logs: `gbear-scrape-*.log` in Downloads. The header lists `fallbackOrder=`. The footer has a **Cover provider usage** block from `MetadataBackgroundFetcher.ProviderUsage` (`ScrapeSummary.usage`): one `usage provider=…` line per provider with `configured`, `searched`, `covers`, `no_match`, `errors`, `skipped` (no platform mapping, not signed in, or paused after quota / rejected keys), ScreenScraper `ambiguous`, TheGamesDB `requests` and `remaining_monthly_allowance`, then a `covers_by_provider` total line. **`clearAllScrapedMetadata`** wipes covers, ScreenScraper IDs, TheGamesDB / IGDB / SteamGridDB check timestamps, and the disambiguation queue.
- **Covers:** `CoverImageCache` disk cache (`~/Library/Application Support/GBear/cover-cache`); validates decoded `NSImage` before save. New downloads are named by a SHA-256 of their bytes, so one picture is stored once however many addresses it came from. `index.json` maps a cache key to the file so repeat scrapes skip the download. The key (`cacheKey(for:)`) drops ScreenScraper's mirror host and the `devid` / `devpassword` / `softname` / `ssid` / `sspassword` / `output` parameters, which change between replies for the same image. Older files named by address hash are still found and indexed. On first launch after this change, `mergeDuplicateCoversOnce` hashes the folder, points every game's cover and cover list at one copy, and deletes the byte-identical extras (BJ-119). Local folder discovery first; remote appended to `coverImageOptions`; primary respects `preferScreenScraperCovers`. **Library crop** is per-emulator (`CoverAspectRatio`); files on disk are not rewritten. **Multi-disc:** cover + ScreenScraper IDs propagate to siblings in the same `discGroupIDString`.

**Key types:** `MetadataService.swift`, `ScreenScraperClient.swift`, `TheGamesDBClient.swift`, `TheGamesDBPlatformMap.swift`, `IGDBClient.swift`, `IGDBPlatformMap.swift`, `SteamGridDBClient.swift`, `CoverProvider.swift`, `CoverProviderQuota.swift`, `RomFingerprint.swift`, `RomTitleNormalizer.swift`, `MetadataSystemResolver.swift`, `RomPathPlatformResolver.swift`, `MetadataBackgroundFetcher.swift`, `ScreenScraperLibraryView.swift`, `ScreenScraperRegionPriorityList.swift`, `ScreenScraperDisambiguationCoordinator.swift`, `CoverImageCache.swift`.

## ROMM

- **Connection** (`RommCredentials`, `RommClient`): server address and username in `UserDefaults` (`ROMM.ServerURL`, `ROMM.Username`; `http://` is assumed without a scheme), password in the Keychain (`KeychainStore`, service `com.gbear.romm`). Every request uses HTTP Basic auth. **Connect** calls `GET /api/heartbeat` (server version) and `GET /api/platforms`.
- **Platform links** (`RommSync.links`, `UserDefaults` `ROMM.PlatformLinks`, ROMM platform id → `EmulatorProfile.id`): one emulator menu per ROMM platform in the pane.
- **Sync** (`RommSync.sync`; **Sync Now** in the pane and at the end of **Scan Paths**), per linked platform:
  - Fetch `GET /api/roms?platform_ids=…&platform_id=…` in pages of 1000 (ROMM 4 only honours `platform_ids`; older servers `platform_id`) and drop roms whose `platform_id` differs.
  - **Filter** (`RommSync.isGame`): skip hidden files or anything under a hidden folder (`.DS_Store`, `._` AppleDouble), `Thumbs.db` / `desktop.ini`, non-game extensions (text, images, audio/video, xml/dat/db, saves, checksums), and single files whose extension is not in the linked emulator's supported file types (when it has any). Multi-file games (folders) pass. Filtered entries are not matched, added, or counted (`Summary.ignoredFiles`).
  - **Name match** (`RommMatcher`), first hit wins:
    1. **Exact file name** (extension dropped, case-insensitive) against ROMM's `fs_name`.
    2. **Normalized title:** `RomTitleNormalizer.searchQuery` (tags, Switch title ids, underscores, `v0`, ™, junk like NSP/XCI/USA), disc labels removed, accents folded, `&` → and, roman numerals → digits, the/a/an/and/of dropped, words sorted. Local file name, title, and library name are compared with ROMM's `name`, `fs_name_no_tags`, and `fs_name`. So "Legend of Zelda, The - The Wind Waker (USA)" matches "The Legend of Zelda: The Wind Waker" and `Monument-Valley-2.NSP` matches "Monument Valley 2".
    3. **ROMM title inside the local name** (for cleaner ROMM names): every ROMM word is in the local name (at least two words), exactly one ROMM game fits, the extra local words have no number (so `Crash Bandicoot 3` never matches `Crash Bandicoot`), and they are not another ROMM game's words. "Moomintroll Winters Warmth Switch NSP BASE GAME" matches "Moomintroll: Winter's Warmth".
  - **Discs never cross:** the disc number (`Disc 2`, `CD2`) comes from the file name. Disc 2 matches ROMM's Disc 2, or a disc-less ROMM game (multi-file set). A disc-less local game (`.m3u`, folder) matches every disc of a split ROMM set, so none of them come back as not-on-this-Mac duplicates.
  - **Shared folders:** a local file inside one of the linked emulator's game folders counts as on this Mac even when another, unlinked emulator owns that row (the scanner gives a shared folder's files to the last emulator scanned). It gets the ROMM fields and its roms are never added as ROMM-only rows. The cleanup at the end of sync leaves those rows alone (`sharedFolderGameIDs`).
  - Matched games with no cover take ROMM's cover. ROMM-only rows are titled with ROMM's name minus any file extension, plus ` (Disc N)` from the file name when ROMM's name has no disc label (ROMM names every disc of a set the same) (`RommSync.displayTitle`).
  - Matched games get `rommStatus = in_romm`, `rommRomID`, `rommPath`, `rommFileName`, `rommHasMultipleFiles`; unmatched local games get `missing`.
  - **ROMM-only games** — only when **Add games to library that are not on this Mac** is checked (next to **Sync Now**; `ROMM.AddGamesNotOnMac`, **off by default**; with it off, sync deletes not-downloaded ROMM-only rows) — become rows with `rommImported = true`, ROMM's cover, and a placeholder `romPath` (`/ROMM/<platform fs_slug>/<fs_name>`), so the inspector shows **Path: Not present**. Blocked as `romm/<id>`, so **Remove from Library** keeps them out.
  - ROMM-only rows whose ROMM game is gone are deleted. Unlinking an emulator clears its ROMM fields and removes its not-downloaded ROMM-only rows. If the user copies the file into a game folder themselves, Scan Paths adds it and the next sync drops the duplicate ROMM-only row.
- **Clear Sync** (`RommSync.clearSync`, with a confirmation): deletes rows with `rommImported == true` whose file is not present and clears every ROMM field on all other games. Downloaded games (file present) stay; no files are touched; login, platform links, and the blocked list are kept.
- **Download** (`RootView.downloadFromROMM` → `RommSync.download(_:into:modelContext:)`): from **Download From ROMM** under Path, or from **Play** when `needsROMMDownload` (in ROMM, file not present; Play launches after the download).
  - The destination is the emulator's **game folder** from Paths (`RommSync.downloadFolders`). If there are several, a confirmation dialog lists them. With none, the user is told to add one. An unmounted folder fails with a message.
  - `RommClient.download` fetches `GET /api/roms/{id}/content/{fs_name}` to a temp file. Single files are moved to `<folder>/<fs_name>`; multi-file games arrive as a zip and are extracted with `ditto -x -k` into `<folder>/<fs_name>/` (one game folder, like the scanner expects).
  - The row's `romPath` becomes the real path and `rommImported` is cleared, so it is an ordinary local game from then on (still **In ROMM** after sync). A spinner shows on the tile and in the inspector while downloading.
- **Scanner:** `GamePathScanner` never prunes `rommImported` rows for a missing file or as a cue sidecar track.

**Key types:** `RommClient.swift`, `RommSync.swift`, `RommMatcher.swift`, `RommSettingsView.swift`, `KeychainStore.swift`.

## Launch pipeline

- **Emulator games:** resolve `EmulatorProfile`; expand `{user_name}`, `{ImagePath}` / `{rom}` / `{ROM}`, and `~` (`LaunchArgumentTemplate` + `GameLauncher.parseArguments`).
- **Sandboxed emulator `.app` (e.g. Astris for Switch):** checked first via the code signature's `com.apple.security.app-sandbox` entitlement (`GameLauncher.isSandboxedApp`, cached per path). Such an app can't read a ROM path from argv, so `launchSandboxedApp` quits any running copy and hands the game over with **`NSWorkspace.open([rom], withApplicationAt:)`** (open-document event, which grants sandbox access); other template arguments are dropped and logged (BJ-128).
- **With non-empty argv:** quit any running copy of that `.app` (so macOS does not merely activate an existing window and drop args), then **`NSWorkspace.openApplication`** with `OpenConfiguration.arguments` and **`createsNewApplicationInstance = true`**.
- **Already-running + empty template:** optional “open document” Apple Event path (avoid for PCSX2/ARMSX2 boot — see bug journal).
- **Standalone / no emulator:** Epic URI path above, else open `.app` or file URL.
- **Do not** rely on `/usr/bin/open --args` from a sandboxed process, or on `OpenConfiguration.arguments` while App Sandbox is enabled — both fail to deliver the ISO path (emulator stays on its game list).

**Key types:** `GameLauncher.swift`, `LaunchArgumentTemplate.swift`.

## Streaming tab (native GBear host)

The Mac app embeds its own **GBear stream host** (ScreenCaptureKit → H.264, HTTP control plane, UDP audio/input). The companion pairs over HTTP and opens a **native video activity** on Android (`GBearVideoActivity`); Sunshine/Moonlight RTSP is no longer required for the default Android desktop stream path.

### Host lifecycle

- **`GBearStreamHostManager`** — in **`ensureReady()`** starts HTTP control (**28765**) and keeps transport listeners bound for the life of the host: TCP video (**28766**), UDP audio subscribe (**28767**), TCP audio downlink (**28769**), UDP input (**28768**). Capture starts on first remote **`stream/start`**; later viewers **attach without restarting encode**. Session create seats **this Mac as Player 1** unless a companion is designated as host player. Stream start/stop is serialized on **`streamOperationChain`**. On stream start, **`GBearLocalOutputMute`** mutes Mac default output; unmutes when the last **video** viewer leaves. **`isVideoStreaming`** mirrors **`videoStreaming`** on the control API.
- **`GBearStreamControlServer`** — pairing queue (`clientKind`: phone vs computer) + **co-op session seats 1–8** (`POST /gbear/v1/session/create|join|join-local|host-player|leave|reassign|cursor-owner|end`); **`stream/start`** auto-joins in **join order** after seating the host player; **`playAsHost`** lets a companion take Player 1 in place of this Mac. **`stream/stop`** leaves the seat and only stops capture when no remaining clients want video. Status includes `session`, `hostPlayerDeviceId`, + `maxViewers` (8).
- **`GBearVideoStreamServer`** / **`GBearAudioStreamServer`** — up to **8** TCP clients; framed **`GBV1`** / **`GBA1`**.
- **`GBearDisplayCapture`** — SCK display + **system audio** (`capturesAudio`); PCM converted to s16le.
- **`GBearStreamInputServer`** — **`GBI1`** touch, **`GBK1`** keyboard, **`GBG1`** gamepad. Incoming GBG1 `joinSeat` is translated to the current assigned seat so **Move to Player N** does not require clients to change packets.
- **`GBearVirtualGamepadManager`** — IOHIDUserDevice pads named **GBear Virtual Pad N**, created only for **occupied** seats. Each pad presents as a wired **DualShock 4** (`054C:09CC`, `GBearHIDUserDevice.c`): the real 64-byte USB report 0x01, answers to the calibration (0x02), MAC (0x12 / 0x81) and firmware (0xA3) feature reports, rumble / light-bar output accepted and ignored, and a per-seat serial, MAC and location ID so apps keep eight pads apart. That is what lets SDL-based emulators (Cemu, RPCS3, ARMSX2, DuckStation, PPSSPP), RetroArch and GameController apps map them with no per-emulator code. Xbox A/B/X/Y go to Cross/Circle/Square/Triangle by position. A centered report is sent on create. Without the Virtual HID entitlement (`GBearVirtualGamepad.isEntitled`) creation is skipped, so remote seats fall back to **`GBearKeyboardPadStandIn`**.
- **`GBearKeyboardPadStandIn`** — presses keys for a remote player's pad (needs Accessibility). Events use the hardware key source (`hidSystemState`), so they still land after `GameLauncher` hides GBear and so in-game polling sees the key as held (BJ-097). The host binds them as that player in the emulator by clicking each slot while the friend presses the button. Each player has their own table (`GBearPadControl.standInKey(seat:)`) and held-key set, so friends never press each other's keys (BJ-116). Players 1–2: A/B/X/Y = keypad 1/3/7/9, L1/R1 = keypad ÷/×, L2/R2 = keypad −/+, L3/R3 = keypad 0/5, Start = keypad Enter, Select = keypad ., Guide = keypad =, D-pad = keypad 8/2/4/6, left stick = F13 up / F16 down / F17 left / F18 right, right stick = F19 up / F20 down / F14 left / F15 right (Player 1 is only remote when a phone stands in for the host). Player 3: letters (A/B/X/Y = K/L/J/I, left stick WASD, right stick TFGH, D-pad E/X/Z/R, bumpers U/O, triggers Y/P). Player 4: number row and punctuation (left stick 1–4, D-pad 5–8, right stick Page Up/Down/Home/End). Players 5–8 have no keys and are dropped (`Route.unrouted`) until virtual pads work. Sticks and triggers are on/off (press above 0.5, release below 0.35). The host's own controller stays a normal controller in the emulator. The control list, labels, and keys live in **`GBearPadControl`** so the stand-in and the **Controller map** panel always agree.
- **Controller map** (`ControllerReceiverMapView`) — button left of **Move to** on each occupied player in **Players**. Popover in the companion mapper's row style: control name (companion labels), what it maps to on this Mac (**Sends Keypad 1**, **GBear Virtual Pad N**, or read directly for the host's own pad), and a live **Pressed** / percent badge with the row highlighted. Header shows **Receiving** / last-signal age. Fed by **`GBearPadInputMonitor`** (`@MainActor`), which `GBearVirtualGamepadManager.apply` / `applyToSeat` update per `GBG1` event; cleared when a seat empties.
- **`GBearHostLocalGamepad`** — host GCController → assigned virtual pad. Yields the controllers while this Mac is a guest (`yieldToGuestSender`), so `GBearGuestGamepadSender` keeps sending to the other host (BJ-096).
- **`GBearStreamGuestManager`** — another Mac pairs as `computerGuest`, receives video/audio, sends local pads as GBG1.
- **`windows-guest/`** — Windows couch-co-op app (`GBearGuest.exe`). UI follows the companion theme (`namespace ui` palette in `GBearGuest.cpp`: background `#0E1014`, card `#1C2028`, primary `#6EB5FF`): a double-buffered header (app bar with the bear icon, rounded card with the host field, owner-drawn seat combo, and GDI+ pill buttons, status dot + text) sized from the monitor DPI, plus a "No picture yet" placeholder in the video area. `GBearGuest.rc` embeds `gbear.ico` (from the Mac app icon) and `GBearGuest.manifest` (Common Controls v6; DPI comes from `SetProcessDPIAware` at startup); DWM gives a dark title bar. `build.sh` compiles the resources with `windres` and links `gdiplus`, `dwmapi`, `uxtheme`, `comctl32`. The joined picture is fitted at the host's shape with black bars (was stretched to the window). **Join** is a `computerGuest` (TCP `GBV1` / `GBA1`, UDP `GBG1` from XInput, keyboard fallback). **Host this PC** is the same control ports as the Mac host so a Mac can **Join another computer**: DXGI capture, Media Foundation H.264 (capped at 1280×720), WASAPI loopback, and a ViGEm Xbox pad per remote seat (seat 1 stays the physical Windows controller). ViGEmBus must be installed on that PC for the remote pad. **Join** by IP uses the LAN ports directly (LAN or a VPN such as Tailscale). **Join** with a pasted `GBEAR1` invite line uses the host Mac's relay instead (BJ-115): `parseInvite` (same rules as the companion, wrapped addresses joined back up; the host box's `hostEditProc` turns pasted line breaks into spaces since a single-line edit drops everything after the first line), `register-device` + `redeem-invite` with the dev bearer, then `runRelaySession` holds one WinHTTP WebSocket (`RelaySocket`, `/v1/ws?deviceId&sessionId&mode=relay`). It sends `hello` on `relay_ready`, answers `ping` with `pong` on the receive thread, takes the seat from `welcome`, queues `GBTL` video to a decoder thread (30 frames, skip to keyframe after a drop or reconnect), plays audio inline, and sends `GBG1` as input frames every 8 ms (50 ms heartbeat). No `welcome` within 45 s fails the join; drops reconnect up to 8 times (2 before the first `welcome`). Hosting on Windows is still direct IP only.
- **`GBearRemoteCoopHost` / `GBearLocalRelayServer`** — two Macs on different networks. The host starts a localhost relay and an outbound Cloudflare tunnel, then copies a `GBEAR1` invite line. The guest redeems it and both sides exchange `GBTL` over WebSocket (video, audio, `GBG1`). No port forwarding. One invite seats up to **7 friends** at once (`GBearLocalRelayServer.maxGuests`, every seat but the host's). The relay room is the host socket plus a guest socket per friend, each with a peer number. Guests only ever see plain `GBTL`, so older companion and Mac guest builds work unchanged. On the host's link, guest frames arrive wrapped in **`GBTP`** (magic + peer byte + the `GBTL` frame) and notices carry `"peer"` (`relay_ready`, `peer_left`, `congestion`). Host frames wrapped in `GBTP` go to one friend (`welcome`, `error`); unwrapped frames (video, audio, `ping`) go to all of them. `GBearRemoteCoopHost` keeps friends by device ID with their seat and current peer number, re-welcomes a friend who reconnects under a new peer number, drops each one 8 s after their own socket leaves, and rewrites the seat byte of each `GBG1` packet to that friend's seat. All friends share one capture and one bitrate, so the slowest link sets the picture rate. A friend who joins when every seat is taken gets "This session is full" (BJ-109). The WebSocket is not on a 30s receive timeout. While the session is up the process stays awake, so launching a game (which hides GBear) does not suspend the relay. If a socket drops, that side reconnects; controller frames are never shed when video backs up (BJ-097). LAN **Join another computer** is unchanged. Capture for this path fits a **1920×1080 @ 30fps** box at the display's own shape (`GBearDisplayCapture.fittedSize`, even dimensions; a 1512×982-point MacBook sends 1662×1080, a 16:9 screen 1920×1080), so there are no baked-in black bars and viewers fit the picture without stretching (BJ-114). The same applies to Wi‑Fi streams, where the phone's requested size is the box with `GBearVideoTuning.relay`: High profile without B-frames, a keyframe every 3s, and bursts up to 1.5× the average so busy scenes keep detail. **`GBearRelayBitrateController`** sets the average: it starts at 8 Mbit/s and moves between 2 and 16, climbing 12% after each 4 s stable stretch, but only while the encoder actually sends at least 60% of the target (`noteVideoSent`, ~2 s smoothed), so a still screen cannot push the target up and flood the link when the game gets busy (BJ-113). The host sends a `ping` on the control channel every second and the guest answers with `pong`. If the round trip grows past the baseline, video is queueing, so the rate drops: 30% when the queue passes 150 ms, half when it passes 500 ms (audio shares the socket, so queueing is heard as audio delay). It climbs again after a stable stretch. A guest that never answers pings is capped at 8. Audio goes out in 10 ms chunks through its own send pump with a 20-chunk (200 ms) FIFO, so a large video frame ahead of it no longer makes it discard chunks; only a longer backlog drops the oldest. The companion's `GBearAudioReceiver` keeps at most 200 ms queued and skips ahead after a stall instead of staying behind. Video is never dropped as single frames: once the host send pump or the relay sheds one, both skip until the next keyframe and ask for a fresh one, and the relay sends the host `congestion` (BJ-098). The host Streaming screen shows **Picture: X Mbit/s** under the session status.
- **`GBearGuestVideoWindow`** — on a joining Mac (LAN or invite), the stream opens in its own resizable window with full screen, not a sheet; the first frame sets the window to the picture's shape (`matchVideoShape`). **`GBearGuestVideoRenderer`** draws it: `GBearVideoStreamClient` decodes with VideoToolbox (BGRA, Metal-compatible; the session is only rebuilt when the format changes, not every keyframe) and hands frames straight to the renderer, which fits them into a `CAMetalLayer` with black bars. When the window shows the picture larger than it was sent, **MetalFX spatial scaling** (`MTLFXSpatialScaler`, perceptual mode) enlarges it up to 2× before the final bilinear draw; ~2.2 ms GPU on an M4 for 1662×1080 → 2462×1600 (harness). **Streaming → Join … → Sharpen the picture with MetalFX** turns it off (`gbearGuestMetalFXUpscale`, on by default; hidden on GPUs without MetalFX). `GBearStreamGuestManager.phase` opens it when streaming starts and closes it on leave or failure. Closing the window leaves the session.
- **`StreamingView`** — **Host plays on** (this Mac = Player 1 and uses a slot, so **7 devices** can join; a paired companion standing in frees the Mac slot so **8 devices** can join), Join another computer (join order by default), **Start remote co-op** / **Join with invite**, 8-slot Move-to UI, pairing for phones and computers. **Streaming host → Bitrate** shows the measured video rate over the last second and the encoder target (`GBearVideoStreamServer.bitRateSnapshot`, counted from encoded frames before they fan out to viewers, polled every second through `GBearStreamHostManager.refreshVideoBitRate`). It reads **Not streaming** without a capture. Remote co-op's adaptive target shows up there as it changes. **Bitrate log:** every capture writes `~/Downloads/GBear bitrate <date>.csv` when it stops (`GBearBitrateLog`, owned by `GBearVideoStreamServer`; sessions under 2 s are skipped). A 1 s sampler adds a row even when no frames arrive, so idle stretches read as zeros. Columns: `time, elapsed_s, measured_kbps, target_kbps, frames, keyframes, bytes, max_frame_bytes, lan_viewers, lan_dropped_frames, relay, relay_rtt_ms, events`. `#` lines at the top summarize average / median / p95 / peak rates, totals, and relay round trips (read with `pandas.read_csv(path, comment='#')`). Events come from the server (keyframe requested, target changes, LAN viewers joining/leaving) and from `GBearRemoteCoopHost` through `GBearStreamHostManager.noteStreamEvent` (friend joined/left, frames dropped on this Mac, relay congestion); the slowest friend's ping round trip per second goes to `relay_rtt_ms`. The Streaming host section shows **Bitrate log** with **Show in Finder** for the latest file. **Detached bitrate:** the picture-in-picture button beside **Bitrate** toggles `GBearBitrateOverlay`, a small HUD `NSPanel` (non-activating, `.statusBar` level, all Spaces + full-screen auxiliary, `hidesOnDeactivate = false`, position autosaved) that stays over games, including full-screen ones. It polls `refreshVideoBitRate` itself every second (the Streaming tab's timer stops when the tab is not shown), shows measured and target Mbit/s, the latest remote co-op round trip (`GBearStreamHostManager.relayRoundTripMillis`), and a 60 s graph (measured filled, target dashed), and holds an App Nap activity while open. It is kept out of the stream: `sharingType = .none` plus `GBearCaptureExclusions`, whose window IDs `GBearDisplayCapture` leaves out of its `SCContentFilter` and re-applies with `updateContentFilter` when the set changes mid-stream. Games that take over the display exclusively can still cover it.
- **Host bitrate on guests** — guests see the host's video rate in the top-left of the picture as `Host 7.6 / 8.0 Mbit/s` (measured over the last second / encoder target, the same `bitRateSnapshot` as **Streaming host → Bitrate**). Remote co-op: `GBearRemoteCoopHost.startPings` adds `bitrate` and `targetBitrate` (bits per second) to its once-a-second relay `ping`, so older guests just ignore the extra keys. LAN: `GET /gbear/v1/status` includes the same two keys while video is streaming (`GBearStreamControlServer.setBitRateProvider`, wired in `GBearStreamHostManager`), and guests poll it every second. The badge hides after 4 s with no value (older host, stalled stream). Mac guest: `GBearStreamGuestManager.hostBitRate` + `GBearHostBitRateBadge` in `GBearGuestVideoWindow`, toggle **Streaming → Show the host's bitrate on the picture** (`gbearGuestShowHostBitrate`). Android: `GBearHostBitrate.kt` (fed by `GBearRelayBridge`'s ping handler or a status poll thread in `GBearVideoActivity`), toggle **Stream input options → Show host bitrate** (`stream.showHostBitrate`, read natively as `flutter.stream.showHostBitrate`). Windows: `noteHostBitrate` / `paintHostBitrate` in `GBearGuest.cpp`, always on.

## Companion app (`companion_app/`)

Flutter shell (iOS + Android) for discovery, HTTP pairing with the native Mac host, and LAN streaming.

### Tabs

- **Hosts** — discover Mac via GBear HTTP control plane; **Add IP** (outlined); **Pair** / **Cancel** while a pairing request is pending (`PairingCancellation` + **`POST /gbear/v1/pair/cancel`** on the Mac).
- **Session** — **`GBearHostClient.startStream`** attaches in **join order** (host Mac is Player 1 unless **Play as the host** is on). The Mac’s slot counts toward 8; an 8th device can join only as the host stand-in. Optional slot override at join; Mac **Move to** reassigns after. Opens **Android** `GBearVideoActivity`. **Stop** leaves the seat; capture ends when the last **video** viewer leaves.
- **Controller** — **Co-op pad mode (GBG1)** (default on) **Auto-maps** connected pads (Eden-style key/axis probe) onto GBG1; **Override** listens for a press. Off uses keyboard chords / Swap. Link gamepad + chord UI remains for single-player / shortcuts.
- **Session → Remote co-op with a friend** (Android) — paste the host Mac's whole `GBEAR1 <code> <https address>` invite line (paste button in the field) and tap **Join with invite**. No pairing or LAN IP. `RemoteCoopInvite` parses the line (everything after the code is joined back into one address, since chat apps wrap it at hyphens — BJ-110), registers at the address with the relay's dev bearer, and redeems the code for the session id (same calls as the Mac guest). Native **`startRelayStream`** then opens the player at 1920×1080 (the decoder and surface follow each frame's real size; `GBearVideoActivity.fitSurfaceToVideo` centers the picture at its own shape with black bars, while the whole screen stays the trackpad) as the seat from the host's `welcome`. **Back in the player** asks **Leave remote co-op?**: **Leave** runs `GBearStreamStopCoordinator.stopSession` (closes the relay bridge, frees the seat on the host), **Hide** closes only the picture and keeps the seat, **Keep playing** dismisses (`GBearVideoActivity.showLeaveRemoteCoopDialog`; LAN streams still just hide on Back). Back arrives through an `OnBackInvokedCallback` registered in `onCreate`; with target SDK 36 predictive back it never reaches `dispatchKeyEvent` / `onBackPressed` (BJ-111). While joined, the section swaps the invite box for **Resume stream view** (when hidden) and **Leave remote co-op**; the top **Stop** and notification Stop also leave. **Join as player** is sent as the preferred seat. iOS has no relay bridge yet, so the section is hidden there.
- **Settings** — **Appearance**, Swap, Shortcuts. (The old **Remote co-op** box — coordinator URL, ID token, 6-letter code — was removed; it talked to a coordinator that never runs and could not take the invite line.)

### Android native (GBear video)

- **`GBearVideoActivity`** — TCP `GBV1` reader thread; codec pump on `HandlerThread`; decode profiles (Annex-B passthrough + `c2.android.avc.decoder` first). **`volumeControlStream`**: media volume. Gamepad motion: if **Swap** on, **`GBearGamepadMouseSender`** runs first (left stick → **`GBI1`** cursor); then **`GBearGamepadMapping`** (triggers, hat D-pad, analog stick directions). Keys: **Back** → **`GamepadLinkCapture`** → mapping (including **toggleSwap**) → Swap mouse for **A/B/X** only → swallow other gamepad keys. **`onDestroy`**: Mac **`stream/stop`** only when the activity did **not** exit via **Back** (`leaveViewerWithoutMacStop`).
- **`MainActivity`** (Flutter shell) — **`GamepadInputFilter`** swallows gamepad keys/motion outside the stream viewer; **volume** keys pass through. **`GamepadLinkCapture`** during link (with target **`elementId`**). **`onDestroy`**: best-effort Mac stop if a stream was still marked active.
- **`GBearRelayBridge`** (remote co-op) — one OkHttp WebSocket to the invite's relay (`wss://…/v1/ws?deviceId&sessionId&mode=relay`, 15 s pings). The relay carries the same `GBV1` / `GBA1` / `GBG1` packets as the LAN ports inside `GBTL` frames, so the bridge serves them on **loopback** (bound to `127.0.0.1` explicitly; Android's `getLoopbackAddress()` is `::1`, which IPv4 dialers cannot reach — BJ-108): a TCP port for video (writes `GBV1` as-is, skips to the next keyframe after a drop), a TCP port for audio (adds the 4-byte length the audio reader expects), and a UDP port whose datagrams go back up as `input` frames. `GBearStreamSession.host` becomes `127.0.0.1` with those ports, so `GBearVideoActivity`, `GBearAudioReceiver`, and the gamepad/keyboard senders run unchanged. It says `hello` on `relay_ready` and again whenever the player reconnects its video socket (the host answers with `welcome` and a keyframe), answers host `ping`s with `pong` right on the socket thread (the host's bitrate controller uses the round trip), and reconnects up to 8 times after a drop before ending the session like notification Stop. `GBearHostControlClient.stopStreamOnHost("127.0.0.1")` closes the bridge, so every existing stop path leaves the relay; the host drops the guest 8 s after its socket goes away. Because of that, a viewer that is only being recreated (configuration change) or replaced by a newer `GBearVideoActivity` must not call it from `onDestroy`, or it closes the loopback ports under the new viewer (BJ-107). `stop(reason)` logs the cause.
- **`GBearAudioReceiver`** — prefers **TCP 28769** (length-prefixed `GBA1`); falls back to UDP after `GBAS` subscribe on **28767**. Separate network and playback threads; `AudioTrack` buffer ~150 ms with low-latency mode; small PCM queue to avoid blocking the socket reader.
- **`GBearInputSender`** — relative cursor, tap/drag gestures on the video `SurfaceView` → UDP `GBI1` to Mac (background thread). Tunables in **Settings → Controllers → Touchpad (stream view)**. Primary pointer path during native stream (no Moonlight mouse-emulation toggle).
- **`GBearRemoteInputPlayback`** (Mac) — maps normalized touch to the **captured display** frame; Y uses `minY + ny × height` so finger-up on the phone moves the cursor up on the Mac.
- **`GBearStreamLog`** — writes `gbear_stream.log` under app files dir for export/debug.
- **Appearance (companion)** — **Settings → Appearance**: primary text color presets (White, Purple, Lavender, Blue, Mint, Peach) or **Custom** RGB sliders. Default on fresh install is **Mint** (`#80CBC4`). Persisted in `companion.appearance.primaryTextColor`; `CompanionApp` rebuilds `CompanionTheme.dark(primaryText:)` when the value changes (`CompanionAppearanceSettings.themeRevision`). The color drives **`outlinedButtonTheme`** (Hosts **Add IP**, **Pair**, **Cancel**) and **`chipTheme`** (mapping/shortcut key chips: transparent fill, matching outline and label).
- **Stream shortcuts (Android)** — **Settings → Shortcuts**: named keyboard chords (multi-key). Default **Close app** = **Command + Q** (macOS quit foreground app); upgrades a stored ⌘⌥Esc default on launch. Stored in `stream.shortcuts` SharedPreferences; native overlay reads the same JSON. **`GBearStreamSession.keyboardSender`** is shared for the whole stream (survives leaving `GBearVideoActivity` with Back). Notification **Shortcuts** opens a picker on the video overlay or, if the viewer is closed, a Flutter sheet + `fireStreamShortcut`. Chords are sent as **`GBK1`** UDP on **28768** (~140 ms hold). Verified Jun 3 2026 with Mac **`GBearKeyboardPlayback`** VK table fix.
- **Controller mapping (Android)** — **Controller** tab: elements → **chords**, **Link gamepad**, or **Assign Swap**. Includes **left/right stick** cardinal directions (held while deflected; separate from L3/R3). **Link** waits for the control matching the row (e.g. push **right stick up** for **Right stick up**; D-pad rows accept hat or stick). Many pads report D-pad as **`AXIS_HAT_X/Y`** — **`handleHatDpad`** sends chords without blocking Swap when hat is centered. Manual links use synthetic key codes in **`GamepadKeyCodes`** for stick directions. **A / B / X** and **left stick** directions cannot **Assign Swap**. **`GBearGamepadMapping`**: keys, triggers, hat, sticks; **`toggleSwap`** on each **ACTION_DOWN** (no stuck latch). Bindings reload from prefs in the stream view; **`GBearKeyboardSender`** survives **Back**.
- **Swap mouse mode (Android)** — Notification **Swap** or **Assign Swap** toggles **`swapMouseModeActive`**. While on: left stick → cursor (**Swap stick cursor speed** in Settings); **A** click, **B** right-click, **X** drag; other mappings (Y, bumpers, right stick, D-pad chords, etc.) still fire. **`releaseAllKeys`** on toggle off avoids stuck modifiers on the Mac.
- **Stream notification (Android)** — channel **`gbear_stream_session_v2`**. Custom layout: row 1 **Stop | Swap**, row 2 **Controller | Shortcuts**; `addAction` fallback on OEMs that collapse custom views. **`GBearStreamNotificationReceiver`**: **Stop** → **`GBearStreamStopCoordinator.stopSession`** (deactivate session, dismiss notification, finish **`GBearVideoActivity`** or end log file, background Mac **`stream/stop`**, optional Flutter **`notifyFlutterStreamStoppedExternally`**); **Swap** → **`GBearStreamSwapActions.toggle`**; **Controller** / **Shortcuts** → mapping overlay or shortcut picker. No `CLOSE_SYSTEM_DIALOGS` broadcast (crash fix). Best-effort shade collapse after the action.

**Key types:** `gbear_host_client.dart`, `streaming_bridge.dart`, `remote_coop_invite.dart`, `GBearRelayBridge.kt`, `stream_controller_mapping_store.dart`, `stream_touch_settings.dart`, `gamepad_elements.dart`, `gamepad_swap_toggle.dart`, `controller_mapping_section.dart`, `GBearVideoActivity.kt`, `MainActivity.kt`, `GamepadInputFilter.kt`, `GamepadLinkCapture.kt`, `GBearGamepadMouseSender.kt`, `GBearGamepadMapping.kt`, `GamepadKeyCodes`, `GBearStreamStopCoordinator.kt`, `GBearStreamSwapActions.kt`, `GBearStreamNotificationHelper.kt`, `GBearStreamSession.kt`, `GBearKeyboardPlayback.swift`, `GBearStreamHostManager.swift`, `GBearStreamControlServer.swift`, `GamepadElementCatalog.swift`.

### Keyboard chord codes (companion → Mac)

Companion labels use Moonlight’s Windows virtual-key codes (`moonlightKeyCode = (0x80 << 8) | vk`). Mac playback maps the low byte through a **US ANSI VK → `CGKeyCode`** table (see `GBearKeyboardPlayback.swift`). Example: **Q** is Windows `0x51` → Mac key code **12** (`kVK_ANSI_Q`), not `0x51 - 0x41`. Mac-specific modifiers:

| UI label | Windows VK | Mac key |
|----------|------------|---------|
| Option | `0xA4` | Left Option |
| Option (right) | `0xA5` | Right Option |
| Command | `0x5B` | Left Command |
| Command (right) | `0x5C` | Right Command |

Legacy bindings that used **Alt** (`0x12`) still map to left Option on the Mac.

### Phone export log (what to look for)

| Log line | Meaning |
|----------|---------|
| `Rendered frame #N` | Video path healthy |
| `Audio TCP connected` | Phone opened TCP downlink on **28769** |
| `Audio packet #N` | `GBA1` frames received and queued for playback |
| `AudioTrack started … buf=…` | Playback started; `buf` should be tens of KB, not multi-MB |
| `Audio subscribed` | UDP fallback path only (TCP preferred) |
| `Input UDP #1` | Touch packets leaving the phone |
| `Shortcut "…" (Command + Q) → host:28768` | User fired a stream shortcut |
| `Keyboard GBK1 down key=0x805b` | Modifier/key down (e.g. Command) |
| `Keyboard GBK1 down key=0x8051` | Key down (e.g. Q) |
| `Input send failed` / `Keyboard send failed` | Network/firewall or socket error on input port |
| `Back pressed — leaving stream view` | Video UI closed; host stream may stay active until **Stop** |
| `Swap on` / `Swap off` (toast) | Notification or mapped button toggled Swap mouse mode |
| `Gamepad map leftStickUp` / hat | Stick or D-pad chord down/up to Mac |
| `viewer closed` / `activity destroyed` | Back left stream running; destroy may stop Mac if not viewer-only exit |
| `Pairing cancelled` / `Cancelling pairing` | User tapped **Cancel** on Hosts |

## Known constraints / pitfalls

- **Controller page navigation relies on a private SwiftUI class.** `ControllerPageNavigator` finds SwiftUI-drawn buttons on Emulators / Paths / Streaming by the class name `_FocusRingView`. If a macOS update renames it, those titled buttons drop out of controller navigation; pop-ups, switches, text fields and icon buttons (real AppKit controls) keep working.
- **App Sandbox vs launch argv:** Keeping `com.apple.security.app-sandbox` on strips `NSWorkspace.OpenConfiguration.arguments`. Emulator launch requires an unsandboxed Mac app (current `GBear.entitlements`).
- **ARMSX2 / PCSX2 CLI:** Prefer **`-fastboot -- "{ImagePath}"`**. A bare `--` before the ISO is required when the path can confuse option parsing. **`-batch -fullscreen`** often produced a gray GS window even when the ISO did boot (check `~/Library/Application Support/ARMSX2/logs/emulog.txt` for `isoFile open ok` / ELF load).
- **Already-running ARMSX2:** `open -a … --args` without quitting first only activates the existing game-list window and does not apply new argv — `GameLauncher` terminates instances before CLI launch.
- **RPCS3 `dev_hdd0/game`:** Assign the folder to the **RPCS3** emulator profile (not a generic multi-system profile) so folder import and ISO-only file rules apply. After scanner fixes, run **Scan Paths** to rename stale **EBOOT** entries. PSN/HDD (**HG**) installs need `USRDIR/EBOOT.BIN`; disc **GD** data folders without EBOOT are not launchable from this path alone.
- **ScreenScraper** quotas, threading, and API shape can change. Without resolved **`systemeid`**, hash lookup is skipped and fuzzy search may pick wrong consoles (DS/Xbox/NES) or return `no_match`. Run **Scan Paths** so `RomPathPlatformResolver` can infer platform from folder roots; check scrape log for `emulatorSystemeid=nil`.
- **Multi-disc auto-link** uses normalized base titles — enable per emulator on **Paths**; manual link/unlink still available in inspector.
- **SwiftData migration:** new non-optional attributes need defaults or optional types; a prior crash on `preferScreenScraperCovers` was fixed with `= false` on the property. `coverAspectRatioRaw` defaults to `"2:3"`. `screenScraperSystemId` is optional (`nil` = infer).
- **Full-library scrape** is synchronous per game with delays; large libraries take time and network.
- **Native streaming (Android)** is verified: video over TCP **28766** (~99% rendered vs. received); audio over TCP **28769** with Mac output muted during stream; touch over UDP **28768** with Accessibility granted.
- **Audio troubleshooting:** expect `Audio TCP connected`, then `Audio packet #1` and `AudioTrack started` with a modest buffer size. Mac console: `[GBearAudio] phone connected (TCP audio)`, `muted Mac default output`, `sent TCP audio frame #N`. If silent, check phone **media** volume and Mac firewall for **28767** / **28769**.
- **Touch** requires Mac **Accessibility** for **GBear**; phone should log `Input UDP #1`. Rebuild Mac app after input-mapping changes.
- **Keyboard shortcuts** require the same **Accessibility** grant; phone logs `Keyboard GBK1`; Mac Console shows `[GBearInput] GBK1` / `keyboard`. Rebuild Mac app after `GBearKeyboardPlayback` changes.
- **Stream notification** on some OEMs may still collapse custom layouts; two-row inline buttons + `addAction` fallback are both present. Do not rely on `CLOSE_SYSTEM_DIALOGS` from the app (blocked on modern Android).
- **Swap stick sensitivity** is independent of touchpad **Cursor speed**; raise Swap stick speed in **Settings** if the cursor feels too slow after fixing inversion (stick up = cursor up on Mac).
- **Companion iOS** native video receiver is still limited; Android `GBearVideoActivity` is the reference client.
- Use the Mac’s **LAN IP** (e.g. `192.168.1.x`), not `127.0.0.1`, on the phone.
